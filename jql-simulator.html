Every switch you'll need

Native Jira Cloud JQL only. Fields and functions from Marketplace apps (ScriptRunner, eazyBI, Zephyr) are called out separately.

Core fields

  • project space key
  • type / issuetype
  • status · statusCategory To Do / In Progress / Done
  • priority · labels · component
  • assignee · reporter
  • parent epic or parent key
  • sprint · fixVersion
  • created · updated · resolved · duedate
  • "Story Points" = cf[10036] here
  • Flagged · issueLinkType
  • text · summary · description · comment

Operators

  • = != one value
  • IN NOT IN lists ( , , )
  • > >= < <= dates, numbers
  • ~ !~ text contains (fuzzy)
  • IS EMPTY IS NOT EMPTY
  • AND OR NOT ( )
  • ORDER BY f ASC|DESC, … always last
  • -7d -2w -1h "2026-12-31"

History operators

  • WAS WAS IN WAS NOT WAS NOT IN
  • CHANGED
  • predicates: FROM TO BY ON
  • AFTER BEFORE DURING (a, b)
  • work on: status assignee priority
  • reporter resolution fixVersion
  • example: status CHANGED FROM "eQE Testing" TO Development DURING (startOfWeek(), now())

Sprint & version functions

  • openSprints() · closedSprints() · futureSprints()
  • releasedVersions() · unreleasedVersions()
  • earliestUnreleasedVersion()
  • latestReleasedVersion()
  • use with IN, never =

People & date functions

  • currentUser() · membersOf("group")
  • now() · startOfDay() · endOfDay()
  • startOfWeek() · startOfMonth() · startOfYear()
  • endOfWeek() · endOfMonth() accept offsets: startOfWeek(-1w)
  • lastLogin() · currentLogin()

Item-set functions

  • issue in linkedIssues(FLY-24, "blocks")
  • issue in issueHistory() recently viewed by you
  • issue in watchedIssues() · votedIssues()
  • issue in updatedBy("user", "-7d")
  • parent in (FLY-1, FLY-2) children of epics

⚠ Not native Jira Cloud

childIssuesOf(), linkedIssuesOf(), subtasksOf(), issueFunction in … come from ScriptRunner or Data Center Advanced Roadmaps. If a blog post uses them, they won't work in plain Cloud JQL. In Cloud, use parent = KEY. With Plans (Premium), issue in portfolioChildIssuesOf(KEY) walks the whole hierarchy.

The simulator

Three legs to cruising altitude

Each challenge gives you a request from the line, hints that unlock one at a time, a pre-flight linter, a checker that compares your query with the flight plan, and a one-click run against the sandbox.

How checking works

Pre-flight check lints your JQL for the classic mistakes. Check against flight plan compares your clauses with the reference solution. It's loose, so equivalent queries written differently may not match. The real test is always Open my JQL in Jira: if your results match the expected keys, press Results match: log it to bank the miles. Results marked verified were confirmed on the sandbox. Results marked expected are what the seed data should return, so confirm them with Run in Jira.

Personal results vary

The sandbox was seeded by one instructor account. Anything using currentUser() or BY returns different results for you. Time-relative queries (-7d, startOfWeek()) change as days pass, too.

Maintenance hangar

Spot the bug

Each of these queries is broken or quietly wrong. Find the fault before you open the fix. Paste any of them into a challenge box and run the pre-flight check to see the linter catch it.

1 · The unquoted status

project = FLY AND status = Ready for eQE
Show the fix

Multi-word values need quotes, or Jira reads "for" and "eQE" as extra keywords.

project = FLY AND status = "Ready for eQE"

2 · Equals with a list

project = FLY AND type = Bug, Story
Show the fix

= takes one value. Lists need IN.

project = FLY AND type in (Bug, Story)

3 · ORDER BY in the middle

project = FLY ORDER BY priority DESC AND type = Bug
Show the fix

ORDER BY must be the last thing in the query.

project = FLY AND type = Bug ORDER BY priority DESC

4 · The silent EMPTY trap

-- "Show me everything that isn't blocked" project = FLY AND labels != Blocked
Show the fix

It runs, but it skips every item with no labels at all, which is most of the backlog. Empty values never match !=.

project = FLY AND (labels != Blocked OR labels is EMPTY)

5 · Function with equals

project = FLY AND sprint = openSprints()
Show the fix

Sprint functions return a list of sprints, so use IN.

project = FLY AND sprint in openSprints()

6 · Copied from Teams

project = FLY AND “Story Points” = EMPTY
Show the fix

Two faults: curly "smart" quotes from a chat or doc, and = EMPTY instead of is EMPTY.

project = FLY AND "Story Points" is EMPTY

7 · Bonus: the escaping OR

project = FLY AND type = Bug OR labels = customer-reported
Show the fix

AND binds tighter than OR, so this returns FLY bugs plus every customer-reported item in every space you can see. Parenthesize.

project = FLY AND (type = Bug OR labels = customer-reported)

8 · Bonus: history on the wrong field

project = FLY AND labels WAS Blocked
Show the fix

WAS and CHANGED only work on status, assignee, priority, reporter, resolution and fix version. For labels you need the item history, an automation rule that stamps a field, or eazyBI.

project = FLY AND labels = Blocked
Instrument panel

Metrics you can fly with JQL

JQL alone doesn't divide or chart over time, but saved filters plus dashboard gadgets get you surprisingly far. When you need ratios and trends, hand the same filters to eazyBI in Level 3.

↩ Bounce-back rate from eQE

The share of work that failed quality engineering this month. Rising means stories reach eQE half-baked.

project = FLY AND status CHANGED FROM "eQE Testing" TO Development DURING (startOfMonth(), now())
project = FLY AND status WAS "eQE Testing" DURING (startOfMonth(), now())

Gadget: two Filter Results gadgets side by side, and divide in your head. For a trend line, use eazyBI's transition measures.

🔁 Carry-over

Work that was in a finished sprint and is still in the current one. It's a planning-accuracy signal, not a blame list.

project = FLY AND sprint in closedSprints() AND sprint in openSprints()

Gadget: Filter Results showing Sprint and Story Points columns. Review it in retro.

🕰 Aging WIP

In-progress work whose status hasn't moved in a week. These are the items to swarm at stand-up.

project = FLY AND statusCategory = "In Progress" AND NOT status CHANGED AFTER -7d ORDER BY updated ASC

Heads-up: the sandbox was seeded today, so this returns nothing until a week has passed. Gadget: Two-Dimensional Filter Statistics, Status × Assignee.

🚧 Flagged & blocked

Everything flagged as an impediment, labeled Blocked, or with an inbound blocker.

project = FLY AND statusCategory != Done AND (Flagged = Impediment OR labels = Blocked OR issueLinkType = "is blocked by")

Gadget: Filter Results at the top of the team dashboard. The same JQL works as a board swimlane.

✅ Ready hygiene

"Ready" items that fail the Definition of Ready. Use it to keep refinement honest.

project = FLY AND status = Ready AND ("Story Points" is EMPTY OR issueLinkType = "is blocked by")

Missing acceptance criteria can't be found reliably with text search. Pair this filter with Rovo's Improve Story or a quick human pass. Gadget: Filter Results plus a daily subscription to the PO.

Are bugs arriving faster than they're fixed?

project = FLY AND type = Bug
